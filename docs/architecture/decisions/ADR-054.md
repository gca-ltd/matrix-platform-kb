# ADR-054: Pipeline board visibility prefs — Qobrix-only filter & Won/Lost columns

**Status**: Accepted  
**Date**: 2026-09-03  
**Scope**: Matrix Sales Automation (Pipeline board / table)  
**Related**: [ADR-052](ADR-052.md) (merge contract, `saved_here` D7);
[security-model.md](../../platform/security-model.md) § service-harvested cache;
[api-contracts.md](../../platform/api-contracts.md)

## Context

Two backlog items from the 2 September broker session (Sergey Lobov, Sergey
Seregin, Milan) asked to:

1. Remove **Won** and **Lost** from the kanban — they are deal statuses, not
   stages, and the two extra columns clip opportunity titles.
2. Hide **Qobrix-only** (elephant-marked) deals from the Pipeline — they crowd
   the board, but hiding them outright removes the only path to adopt such a
   deal into the app (Milan's caveat).

Both were marked "Needs a decision". Product settled on **user toggles, both
hidden by default**, remembered on the device, with an always-visible way to
bring Qobrix-only deals back.

## Decision

### D1 — Per-user UI prefs in localStorage (not App DB)

Keys are app-suffixed (`matrix.sales.pipeline.{pref}.{appSuffix()}`) so staging
and production deploys on the same host do not collide (SR000512). Missing key
means hidden. Cross-device sync is out of scope.

### D2 — Defaults: both hidden

- `showQobrixOnly = false` → client sends `saved_here_only: true` to the board EF.
- `showClosedColumns = false` → kanban uses `PROGRESSION_STAGE_COLUMNS` (five
  columns). Explicit stage chips `won` / `lost` override the pref on; chip
  `open` always hides them. Table view is unchanged (no columns; stage chips
  already filter).

### D3 — Server-side `saved_here_only` (exact totals)

Post-filtering a merge page would lie about `total` and stage counts
(`mergeTotal` is algebraic over Qobrix `pagination.count`). When
`saved_here_only` is true, `qobrix-pipeline` **skips the Qobrix merge** and
pages App-DB `opportunities` the viewer may see (app-authored **and** promoted
copies). That set is exactly the complement of Qobrix-only preview rows.
`totalExact: true`. Parameter defaults to `false` so older clients keep the
merge path.

Tabs covered: `opportunities_board`, `board_stages`, `board_stage`.

### D4 — Viewer scope is required on the materialised leg

App DB `opportunities` holds mass-imported Qobrix copies. Serving them under
`service_role` without a viewer predicate is the
[service-harvested cache anti-pattern](../../platform/security-model.md).
`fetchMaterializedOpportunities(tenant, includeClosed, viewer, …)` takes a
**required** `viewer`; restricted scopes filter on `x_assigned_user_id` /
`owner_team_id`. Unrestricted scopes remain tenant-scoped only. PII masking on
the page rows is preserved.

### D5 — Disclosure strip when Qobrix-only is hidden

A persistent “Deals that live only in Qobrix are hidden — Show” strip (same
pattern as the open-out-of-range disclosure) answers Milan's caveat without
forcing the toggle on for everyone.

## Consequences

- Positive: cleaner default board; honest pagination; adopt path preserved.
- Positive: when closed columns are hidden, kanban bootstrap skips two Qobrix
  per-column waves.
- Trade-off: materialised mode is capped at `APP_AUTHORED_LEG_CAP` (5000) and
  reports `truncated` past that — acceptable for the filtered set size today.
- Trade-off: prefs are per-browser, not per-user across devices.
