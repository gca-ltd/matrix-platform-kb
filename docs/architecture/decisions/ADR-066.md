# ADR-066: An app records how its screen is used, in its own database, without the text people type

**Status:** Accepted
**Date:** 2026-11-16
**Scope:** Matrix Sales Automation first. The same shape is available to other Matrix apps.
**Related:** [ADR-045](ADR-045.md), [security-model.md](../../platform/security-model.md), [performance.md](../../platform/performance.md)

## Context

Rebuilding the MSA user flow needs evidence: which control is used, how long a field is edited, which forms are abandoned, which saves fail. A weekly count of saved rows (`broker_usage_weekly`) shows outcomes, not the path that led there.

A third-party product analytics service would be a second store, off the server, and could not join a click to the opportunity it changed. A session replay would capture client names, phones, and emails that are on the screen.

ADR-045 already records one operational failure (`sso_permission_load_failures`) as rows the app writes about itself. This is the same idea for product behaviour.

## Decision

1. The journal is `ui_events` on the app database, partitioned by month, with `ui_event_catalog` naming every event and `ui_events_daily` keeping counts after raw rows older than 180 days are dropped.
2. The browser sends batches to `log_ui_events`, a `SECURITY INVOKER` function. The user and tenant come from the SSO JWT. There is no service role. `authenticated` may insert its own rows and may not select them. The owner reads the journal.
3. A field edit stores durations and character counts. The characters are not stored. Search stores the length of the query. A select stores a short screen code. Property names that would hold typed text are dropped in the browser and again in SQL.
4. Controls are labelled at build time (`data-track`). Password fields are excluded. The label map is committed next to the dictionary so a person and a query see the same names.
5. The write is batched and is not on the path that paints the page.

## Consequences

- A question such as "how long is an opportunity description" is a join from `field_edit` lengths to the saved row, or a query on the saved row itself.
- Staff must be told, before this runs in production, that actions are recorded and the typed text is not. That notice is an HR and legal step, not a migration.
- Other Matrix apps can copy the table, the function, and the build-time labels. They do not share MSA's table.
