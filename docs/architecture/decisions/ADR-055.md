# ADR-055: Immutable release directories + atomic symlink publish for github-watcher

**Status**: Accepted  
**Date**: 2026-09-04  
**Scope**: `sharpsir-group/github-watcher` (intranet Matrix SPA deploys)  
**Related**: [operations.md](../../platform/operations.md);
workspace rule `github-watcher-repo-config.mdc`;
workspace rule `no-agent-deploy-sh.mdc`

## Context

`github-watcher` is the only production deploy path for the intranet Matrix SPAs. Until
2026-09-04 it published with `rm -rf "$DEPLOY_PATH"/*` followed by `cp -r dist/*`, and ran
`eval "$BUILD_CMD"` with no timeout.

Three failure modes showed up in production:

1. **Hung `npm install`** (IPv6 / registry stall) held the single concurrency slot and blocked
   every other app until an operator killed the process.
2. **Non-atomic publish** left a window where the live site was empty; a failed `cp` could still
   stamp `index.html` and log success because `main` was invoked under `if main`, which
   suppresses `set -e`.
3. **Uniform backoff** treated a network hang the same as a compile error, so recovery needed a
   manual empty retrigger push.

Agents must never invoke `deploy.sh` (`no-agent-deploy-sh.mdc`); hardening has to live inside
the watcher itself.

## Decision

### D1 — Immutable releases outside htdocs

Build output is copied to `/opt/bitnami/apache/releases/<subpath>/<sha>/`. The public
`deployPath` (`/opt/bitnami/apache/htdocs/<subpath>`) is a **symlink** to the current release.
Apache already has `Options FollowSymLinks` and `AllowOverride All` on htdocs, so no vhost
change is required; `.htaccess` inside the release dir continues to apply.

### D2 — Atomic symlink swap via `mv -T`

Publish creates `deployPath.new.$$` → release dir, then `mv -T` over `deployPath`. That is a
single `rename(2)`. `ln -sfn` is forbidden (unlink + symlink has a missing-path window).

On first deploy of an app, any existing real directory is moved to
`releases/<subpath>/legacy-<timestamp>/` so rollback always has a previous target.

### D3 — Timeouts and classified exit codes

| Code | Meaning | Recovery |
|---|---|---|
| `0` | Success | Clear backoff |
| `10` | Deterministic (compile / empty dist / stamp mismatch) | Exponential reconcile backoff |
| `20` | Transient (timeout, git fetch, npm network) | Fast retry 30s then 120s, then tick backoff |
| `30` | Fatal env (missing clone, lock, disk) | Max backoff |

`deploy.sh` wraps the build in `timeout -k 30s ${BUILD_TIMEOUT:-900}s`. The webhook parent
spawns the script `detached: true` and kills the process group after `deployTimeoutMs`
(default 20 min) so a wedged child cannot hold the slot.

### D4 — Dirty re-enqueue and auto-rollback

A webhook for a target that is already running/queued is marked dirty and re-enqueued on
completion (no longer dropped until the next 5-minute reconcile). After the symlink swap, the
served `<!-- deploy: … -->` stamp must match the pinned `TARGET_SHA`; mismatch auto-rolls the
symlink back to the previous release. Loopback `POST /rollback` exposes the same swap for
operators.

### D5 — Pin SHA + clean tree before build

`TARGET_SHA` is read once from `origin/<branch>` after fetch. The working tree is
`git reset --hard` to that SHA, `git clean -ffd` (keeping `node_modules`), and `dist/` is
removed before build so a broken commit cannot build from leftover untracked files.

## Consequences

- Apps migrate lazily on their next push; no big-bang cutover.
- Operators roll back with `POST http://127.0.0.1:9001/rollback` without rebuilding.
- Disk use grows by up to five releases per app; prune runs after every successful deploy.
- `/status` now reports `symlinkTarget` and `stuckForMs`.
- KB `operations.md` must describe the watcher as the Matrix SPA deploy path (not manual rsync).

## Alternatives considered

- **rsync `--delete` into the existing directory** — smaller change, but not atomic and this
  host does not ship `rsync`.
- **Build into `deployPath.new` then `mv` directories** — atomic-ish without symlinks, but still a
  brief 404 window and no retained previous release for rollback.
