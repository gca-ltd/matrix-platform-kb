# ADR-045: Permission reads fail loud, not fail closed (or open)

**Status**: Accepted  
**Date**: 2026-08-28  
**Depends on**: security model L1 (`sso_role_configurations`), app-template `ProtectedRoute`  
**Scope**: All Matrix watcher SPAs + `matrix-apps-template-2-1` / `2-2`; SSO telemetry

## Context

Page access is **not** in the SSO JWT. SPAs load `sso_role_configurations`
(or legacy `app_permissions`) via PostgREST with the SSO Bearer token. When
the 1-hour access token expires and `postgrestAccessToken()` returns
`undefined`, supabase-js falls back to the anon apikey. RLS on
`sso_role_configurations` is `FOR SELECT TO authenticated`, so the read
errors or returns zero rows.

Historical client behaviour:

| Path | On error | User effect |
|------|----------|-------------|
| `useRoleConfig` (most apps) | `return null` → empty config | Non-admin (e.g. Broker) saw **Page Not Available** until full re-login |
| `usePagePermission` (FM, Analytics) | `return true` | Silently **granted** every gated page |

`ProtectedRoute` only waited on auth `loading`, not on the permissions query,
so "still loading" looked identical to "denied". Re-signing in via the Agency
Hub fixed the fail-closed case by clearing the React Query cache and minting
a fresh token — which made the bug look like a role misconfiguration.

## Decision

### D1 — Three-state permission gate

`ProtectedRoute` (and equivalent page gates) must distinguish:

1. **Loading** — role-config / page-permission query still pending → branded spinner ("Checking permissions…").
2. **Load failed** — query errored after retries → **"Couldn't verify your permissions"** with Retry and Sign in again. Never reuse the "not included in the permissions for {Role}" copy.
3. **Denied** — successful load, page key absent from `pages` → real Page Not Available screen.

### D2 — Fail loud in the query function

- Guard: if `postgrestAccessToken()` is empty, **throw** (do not attempt an anon read).
- On PostgREST error, **throw** (do not `return null` / `return true` / `return []`).
- React Query records an error state, retries with backoff, and does not cache a fake success under `staleTime`.

### D3 — Telemetry

SSO table `sso_permission_load_failures` + EF `log-permission-failure`
(`verify_jwt: false` — the caller's token is often expired by definition).
Clients POST best-effort on final failure; EF dedupes per user+app within 60s.
Service-role writes; `system_admin` SELECT.

### D4 — Legacy `app_permissions` apps

FM and Analytics keep allow-by-default when a **row is missing** (product
choice for unconfigured apps), but still throw on token/query failure so they
never fail open on a broken session.

## Consequences

- Brokers (and other `self`/`team` scopes) no longer see a sticky false denial after a token gap.
- FM/Analytics no longer silently open gated pages on a token gap.
- Operators can query `sso_permission_load_failures` when users report access issues.
- `postgrestAccessToken()`'s anon fallback remains for other PostgREST paths that intentionally allow anon RLS; permission reads opt out.
