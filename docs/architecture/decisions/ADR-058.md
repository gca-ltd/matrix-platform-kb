# ADR-058: MSA MCP — one server, URL-mode connect link, MCP OAuth

**Status:** Accepted  
**Date:** 2026-09-29


> **Superseded in part by [ADR-059](ADR-059.md).** Auth is `none`, `api_key`, `oauth_user`, or `oauth_service`. Custom auth headers and the old mode names are retired. See the [MCP profile](../../platform/mcp/README.md).

## Context

Digital Employees and desktop MCP clients need read-only access to Matrix Sales Automation as the signed-in user. The Qobrix MCP is a separate resource server plus authorization server and stores source API keys. ITSM's `mint-delegated-token` path (ADR-032) is not the pattern for this server.

## Decision

One Node process (`gca-ltd/matrix-sa-mcp`) at `https://intranet.sharpsir.group/msa/mcp` serves:

- **the retired signed-header path** (MCP out-of-band connect link). Digital Employees signs `X-Chat-*` with a shared HMAC. A cold user gets a one-time link. Matrix SSO returns the user's own access and refresh tokens into an encrypted per-user vault. The signed email must match. An existing SSO browser session completes without a password form.
- **MCP OAuth authorization** (RFC 9728, RFC 8414, RFC 7591, PKCE S256, RFC 8707) for Claude and Cursor, using the same SSO login and the same kind of vault, keyed per user and client.

Reads go to the MSA App DB with that user's JWT. There is no service-role key. Reports are computed from rows the user can read. Privileged `SECURITY DEFINER` functions and edge functions are not called.

Use these names instead of the internal Qobrix "stdio–D" labels: **the retired signed-header path** and **MCP OAuth authorization**.

## Consequences

- Digital Employees' `oauth_user` client path sends the signed headers and honours `structuredContent.auth_required`. Group threads never receive the link.
- `mcp/contract.json` in the MSA repo is the sync contract. The MCP vendors a copy. A guardrail fails an MSA push when a contracted column disappears.
- Divergence from ADR-039: resource and authorization endpoints are one process; the vault holds SSO tokens, not source API keys; ADR-032 is not used.
