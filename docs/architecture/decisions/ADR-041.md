# ADR-041: Single-path Qobrix MCP with request-scoped auth (oauth_user)

**Status**: Accepted  
**Date**: 2026-08-22  
**Depends on**: [ADR-039](ADR-039.md), [ADR-040](ADR-040.md)  
**Scope**: `qobrix-crm-mcp` HTTP server, Apache intranet proxy

## Context

Qobrix MCP production runs **oauth_user** (`oauth_user`) for Claude.ai, Dust.tt and
Cursor. Matrix Digital Employees connects as an **OAuth user client** (`oauth_user`)
with per-principal Bearer tokens — the same oauth_user path after login.

Mode cannot be inferred from an anonymous HTTP request alone. A single `/mcp`
endpoint uses explicit client signals instead of separate URLs.

## Decision

### D1 — Single `/mcp` with auto routing

One `qobrix-crm-mcp` process with `the retired auto-routing setting=1` (legacy alias
`the retired dual-routing setting`):

| Request signal on `POST /mcp` | Auth mode | Clients |
|-------------------------------|-----------|---------|
| `Authorization: Bearer …` | oauth_user | Claude, Dust, Cursor, Digital Employees (after OAuth) |
| `X-Chat-User-Id` (+ signed `X-Chat-*`) | the retired signed-header path | ragchat / loopback callers only |
| Neither | oauth_user | Claude probe → 401 + `WWW-Authenticate` |

There is **no** `/mcp-c` path.

### D2 — Request-scoped auth in ALS

`request-context.ts` carries `authMode` per MCP request so `client.ts` and
`tools/session.ts` use `getRequestAuthMode()` instead of the global env.

## Consequences

- Apache: proxy `/qobrix-crm/connect`, `/oauth/callback`, `/mcp`.
- Digital Employees registers Qobrix as `auth_mode = oauth_user` at `…/qobrix-crm/mcp`.
- ADR-040 § D4 (`AUTH_REQUIRED` agent contract) is **superseded** for all servers;
  tool results are relayed verbatim.
