# ADR-065: MSA writes for an agent go through a separate Edge Function

**Status:** Accepted
**Date:** 2026-11-12
**Scope:** MSA App DB `rpoeezssicpzexarmwqq`, edge function `msa-actions-mcp`, Digital Employees employee MSA Navigator
**Related:** [ADR-049](ADR-049.md), [ADR-062](ADR-062.md), [security-model.md](../../platform/security-model.md)

## Context

Brokers were creating Opportunities through a Claude browser extension because the MSA screen is hard to follow. The assistant should do that work itself, inside the broker's own rights, from the Playground.

The read-only MSA MCP already accepts the broker's Matrix SSO JWT (ADR-062). That token can write. The server does not write only because its code refuses to. Putting writes in the same process would share the OAuth path used by Claude and Cursor, and a mistake in that code would open writes to those clients. It would also take Mia's reads down with a write bug.

ADR-049 already splits the Hungary catalogue the same way: `hu-properties-mcp` reads, `hu-leads-mcp` writes.

A service-harvested cache is not a substitute. In August 2026 a cache filled by a service account exposed about 46,000 opportunities with client details to people who could not see those rows. This path must not have a service role.

## Decision

1. Writes live in the edge function `supabase/functions/msa-actions-mcp` on the MSA App DB. The read server at `/msa/mcp`, its contract, and its OAuth stay as they are.
2. The function accepts only a Matrix SSO JWT, verified against the SSO JWKS with issuer, audience, and expiry. There is no HS256 fallback and no OAuth.
3. The function has no service role. It calls PostgREST with the anon key and the broker's bearer, and only functions named `assistant_*`. Those functions are `SECURITY INVOKER`. The existing `SECURITY DEFINER` stage, qualify, and contact functions keep their own caller checks, and the wrappers pass `p_skip_gates = false`.
4. Each write takes an idempotency key. A repeat returns the first result. Won and Lost are a separate tool. Digital Employees asks the broker before that tool runs, until the CRO decides otherwise.
5. MSA Navigator is a new employee in the Sharp SIR tenant. It receives the read server and this function. Mia does not receive this function.

## Consequences

- A bug in the write function cannot add a write tool to Claude or Cursor, and cannot take down Mia's reads.
- The broker sees and changes only rows their own scope already allows. A self-scope broker does not see a colleague's new Opportunity.
- Creating an Opportunity for a contact owned by someone else still freezes it for an Area Manager, as the screen does.
- The screen that creates an Opportunity is not switched onto `assistant_create_opportunity` in this change. That waits until the pilot holds, and it goes through a production promotion.
