# ADR-061: Host the Digital Employees Playground as a vendored module

**Status:** Accepted. On Sales Automation `main` (`/msa-staging-main/`) and `cdto`. Production `/msa/` waits for a `main` → `prod` promotion.
**Date:** 2026-10-12
**Scope:** Digital Employees Playground, Matrix Sales Automation
**Related:** [vendored-modules.md](../../platform/vendored-modules.md);
[api-contracts.md](../../platform/api-contracts.md);
[app-catalog.md](../../platform/app-catalog.md)

## Context

The Playground is the full chat surface: every digital employee, the per-user inbox, training, approvals, insights, voice, and read-aloud. The public Conversations API (`converse`, `mxde_` keys) and the MCP servers do not carry that surface. A host that needs it has to call the same SSO-authenticated edge functions the Playground already uses.

## Decision

1. Digital Employees owns the module at `src/features/de-playground`. A host vendors a byte-identical copy and checks a sha256 manifest. The host does not iframe the page and does not keep a one-time fork.
2. The host calls `configureDeClient` with its own SSO token and the Digital Employees project URL. Chat, runs, employees, training, and voice go to that project's edge functions. The user's Matrix SSO JWT is the credential. There is no new public API.
3. In Matrix Sales Automation the page is `/playground`, in a Digital Workforce sidebar group, on `main` (`/msa-staging-main/`) and `cdto`. It opens when the role has the `playground` page key. Every MSA role has that key by default; an administrator removes it in Role Configuration. The Digital Employees client in `allowed_apps` is not a gate. That claim is the union of every role the person holds and does not change when they switch roles, so it cannot control one role. Training is shown only for scopes `global`, `org_admin`, and `system_admin`.
4. The page gate is the host's page-key check. The edge functions still accept any valid Matrix SSO JWT. A server check (an admin scope for training and employee-config apply, on top of a valid SSO JWT) is a follow-up.
5. The existing realtime topic `runs:<tenantId>` stays a public broadcast of refresh pings. It does not carry conversation content.

## Consequences

Sales Automation shows the same Playground Digital Employees shows, for every role that has the Playground page. Every MSA role has it by default. Changing the module means changing it in Digital Employees and re-vendoring. Production `/msa/` picks this up only when `main` is promoted to `prod`.
