# ADR-029: "Contract agreed" maps to the Pending edge; close = settlement; pipeline stage is a projection; per-country collection anchor

**Status**: Accepted
**Date**: 2026-06-10
**Deciders**: Platform team + Pipeline team
**Related**: [ADR-026](ADR-026.md) (event-sourced transaction model; `cdl-listing-lifecycle` EF — this ADR refines its edge semantics, changes nothing structural), [ADR-028](ADR-028.md) (per-country Commission Engine — gains the collection-anchor rule param), [ADR-025](ADR-025.md) (`document` resource — receives archived contracts), [transaction-lifecycle.md](../../business-processes/canonical-processes/processes/transaction-lifecycle.md), [qobrix-data-model.md](../../data-models/qobrix-data-model.md), [matrix-pipeline processes](../../product-specs/matrix-pipeline/wiki/processes.md#offer-to-closing)

## Context

The legacy Qobrix CRM (`raw/qobrix/qobrix_openapi.yaml`, `Contract` schema, titled "Agreement") models the contract as one overloaded entity (`contract_type`: `cos`, `tenancy_agreement`, `listing_for_sale`, `listing_for_rent`, `property_management`) whose status machine **terminates at `agreed`** (`reserved | cancelled | agreed`) — there is no `completed`/`settled` state. Operationally, Sharp SIR has treated "contract agreed" as "deal closed". Conveyance is tracked on a separate, unlinked field (`title_deed_status`: `pending | issued | transferred_to_buyer`), because in Cyprus title deeds can lag the contract by years.

RESO DD 2.0 keeps **two distinct edges** that Qobrix collapses:

1. **Contract signed**: `Property.PurchaseContractDate` ("the date an offer was accepted and the listing was no longer on market"), `StandardStatus → Pending`, HT `ChangeType = Pending`/`Active Under Contract`.
2. **Deal completed**: `Property.CloseDate` + `ClosePrice`, `StandardStatus → Closed`, HT `ChangeType = Closed`.

The unresolved questions: which edge "agreed" triggers, what the Pipeline's "Closed" funnel stage means, what commission collection keys off, and how Qobrix `Contract` rows migrate. The KB previously deferred this ("Contract → no direct RESO equivalent; platform extension needed").

**Key clarification that resolves the tension**: RESO `CloseDate` means **settlement** (purchase fulfilled — final payment + possession), NOT title-deed registration. The CY title-deed lag therefore does not delay canonical `Closed`; only the payment plan does. Qobrix itself proves the distinction by keeping `title_deed_status` separate from `contract_status`.

## Decision

### D1 — Two-edge canon, settlement close, stage as projection

Canonical edges stay strict (ADR-026 unchanged):

| Real-world event | CY / HU / KZ practice | Canonical write |
|---|---|---|
| Reservation + deposit | CY reservation agreement; HU foglaló; KZ deposit | *(future, optional)* `Active Under Contract` — see "Future refinement" |
| **Contract signed** (CoS / adásvételi / договор купли-продажи) | The commercial "deal won" moment | `acceptOffer`: `StandardStatus → Pending`, `PurchaseContractDate = date_of_contract`, escrow locks on |
| **Settlement** (final payment + possession) | CY last installment; HU final price paid; KZ notarized + registered | `closeDeal`: `StandardStatus → Closed`, `CloseDate` = settlement date, `ClosePrice` = final price |
| Title deed transferred | CY only; may lag years | **No canonical event** — project-flavour tracker only |

The Pipeline **funnel stage is a projection, not a column**:

- Stage **"Closed" (deal won)** = `PurchaseContractDate IS NOT NULL` (the agreement event).
- Canonical `StandardStatus = Closed` surfaces as a **"Settled"** badge/substate.
- UI and reporting MUST label the two notions distinctly ("Deal won" vs "Settled").

Mapping `agreed → Closed` directly (the Qobrix-operational reading) is **rejected**: it would redefine `ClosePrice`/`CloseDate` as signature data in comps, the Dash/SIR feed, and IDX — exporting a data-quality defect to the brand network — and would skip `Pending` (escrow locks, under-contract visibility) entirely.

### D2 — Collection anchor: per-country, default "open at agreement, finalize at close"

Commission **collection opens at the agreement event** (`PurchaseContractDate` set / HT `Pending` row) and **reconciliation finalizes at canonical `Closed`** (`finance-erp-webhook` keeps writing `commission_estimate.actual_gci` on close — unchanged). The anchor is a **per-country rule param** in the Commission Engine (already country-scoped + date-versioned per ADR-028):

- **CY**: commission invoiced at CoS signing → anchor = agreement.
- **HU**: sikerdíj due at final contract (often staged with foglaló) → anchor = agreement.
- **KZ**: signing-to-registration gap is days → default anchor works.

### D3 — Qobrix `Contract` migration: hybrid decomposition

| Qobrix `contract_type` | Disposition |
|---|---|
| `cos` / `tenancy_agreement` | **Decompose**: `date_of_contract` → `PurchaseContractDate`; settlement → `CloseDate`; `final_selling_price_amount` → `ClosePrice`; parties (`ContractParty`) → `ContactListings` (+ `Contacts.ContactType → Buyer`/`Tenant`); commission block → app-private `commission_estimate` |
| `listing_for_sale` / `listing_for_rent` | **Mandates** → canonical `Property.ListingAgreement` (`exclusivity: true` → `Exclusive Right To Sell`, else `Open Listing` — verify against actual CY mandate forms at migration time) + `ListingContractDate` + `ExpirationDate` |
| `property_management` + scanned PDFs | ADR-025 `document` rows (`related_resource`/`related_key`); PM contracts have no canonical lifecycle |

`commission_agreed` (UUID → Users; the commission approver) → app-private `commission_estimate.approved_by`. `title_deed_status` → project-flavour tracker (app-private or `x_*` if cross-app need emerges; not canonical).

### D4 — Cancellation mapping: deterministic

- `cancelled` with `date_of_contract IS NULL` (was `reserved`) → **no canonical transaction event**; at most `ContactListings.ContactListingPreference → Discard`.
- `cancelled` with `date_of_contract` set (was `agreed`) → `cancelDeal` → `StandardStatus = Back On Market`, escrow locks released, HT `ChangeType = Back On Market`.

## Future refinement (non-blocking)

Qobrix `reserved` corresponds canonically to `Active Under Contract` (offer accepted, contingencies remain, listing still marketable) — consistent with the Offer-to-Closing flow already documented in the Pipeline spec (Accepted → AUC → Pending → Closed). ADR-026's EF implements only `Active → Pending`; a `reserveListing` action (`Active → Active Under Contract`) is a candidate future enhancement of `cdl-listing-lifecycle`. Until then, reservation lives stage-side only.

**2026-08-06 enrichment (still stage-side):** the CY Sales Automation app now
models Offer Acceptance / Reservation Agreement / Deposit Paid, a per-unit
lock, and a three-working-day deposit deadline on `public.reservations` (see
[`reservation-lifecycle.md`](../../business-processes/canonical-processes/processes/reservation-lifecycle.md)).
That work deliberately does **not** write CDL `Active Under Contract` — it
deepens the stage-side model ADR-029 already authorised, and will feed the
future `reserveListing` action rather than bypass it.

## Consequences

### Positive
- Zero KB divergence: `transaction-lifecycle.md` and ADR-026 stand as written; no EF contract changes required now.
- Broker-facing "Closed" matches commercial reality (contract signed) without corrupting canonical close economics consumed by comps, Dash, and IDX.
- Collection timing matches jurisdictional invoicing practice via one rule param, no new architecture.
- Qobrix migration has a deterministic, lossless disposition for every `contract_type` and every cancellation path.

### Negative / notes
- Two notions of "closed" coexist; every report/UI surface must say which one it shows ("Deal won" vs "Settled").
- The stage projection adds derivation logic (already the pattern — see ADR-026 timeline reads).
- `ListingAgreement` lookup mapping from Qobrix `exclusivity` is provisional until checked against real CY mandate forms.

## Alternatives considered
- **`agreed` → `closeDeal` directly** (business-pragmatic collapse) — rejected: canonically wrong (`CloseDate` = settlement), skips `Pending`, pollutes close economics network-wide, structural KB divergence.
- **Stage "Closed" = canonical `Closed`** (canonical-strict stage) — rejected: won deals would sit in "Contracting" for the whole payment plan; collection would have no trigger at signature.
- **Archive-only migration** (all contracts → `document` rows) — rejected: loses queryable economics/dates needed by variance reporting and comps history.

## Matrix MLS (seller-side)

Developer **payment plan templates** (`payment_plans.installments`) are expanded into per-deal **`unit_installments`** rows at the unit deal Closing contract step (collections tracking: due date, amount, mark paid). This is app-private MLS schema aligned with D2 staged collection; it does not alter canonical RESO `CloseDate` semantics.
