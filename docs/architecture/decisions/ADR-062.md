# ADR-062: A Matrix-owned MCP may accept the caller's Matrix SSO JWT

**Status:** Accepted
**Date:** 2026-10-15
**Scope:** MSA MCP (`mcp/server` in `gca-ltd/matrix-sales-automation`), Digital Employees client
**Related:** [ADR-058](ADR-058.md), [ADR-059](ADR-059.md), [security-model.md](../../platform/security-model.md)

## Context

Digital Employees already holds the person's Matrix SSO access token when they ask a question in the Playground. ADR-058 and ADR-059 then require a second OAuth hop: the chat client stores an opaque MCP token, and the MCP server exchanges it for the same SSO token it could have been given. That second sign-in is what people hit when they ask Mia a sales question.

The MSA MCP and the MSA App DB trust the same issuer (`https://xgubaguglsnokjyudgvc.supabase.co/auth/v1`). A JWT that PostgREST would accept is a JWT the MCP can accept.

## Decision

1. The MSA MCP lives in the MSA repo at `mcp/server`. There is one contract, `mcp/contract.json`. The standalone repo `gca-ltd/matrix-sa-mcp` is archived as `matrix-sa-mcp-superseded`.
2. `POST /msa/mcp` accepts two bearers:
   - a Matrix SSO JWT, verified against the SSO JWKS (`iss`, `aud=authenticated`, `exp`) whose `client_id` or `azp` is on a short allowlist (MSA and Digital Employees);
   - an opaque MCP OAuth token, resolved through the existing vault, for Claude and Cursor.
3. Both paths call the App DB as that user. There is no service-role read.
4. Digital Employees registers this server as `sso_forward`. A Playground turn sends the caller's SSO JWT. A scheduled run with no live session uses the stored `oauth_user` token.
5. This diverges from ADR-059's closed list of four auth types. The justification is that the MCP and the database already trust one issuer, so a second OAuth hop adds a sign-in and no new boundary. Other MCP servers keep the four types. A new fifth type is not a default.

This partly supersedes ADR-058 (separate repo, vendored contract, OAuth as the only way in) and the sentence in ADR-059 that MSA is only `oauth_user`.

## Consequences

- Manager figures come from `SECURITY INVOKER` `kpi_*` functions declared in `mcp/tools.yaml`. A tool cannot call a function that is not on the contract.
- The server is built into `/opt/matrix-sa-mcp/releases/<sha>` by the MSA `@main` watcher hook and switched only after `/msa/mcp/health` answers. The vault and `.env` stay outside the git checkout.
- A client that is not on the allowlist cannot present an SSO JWT. It uses MCP OAuth.
