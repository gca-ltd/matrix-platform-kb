# ADR-051: Live Qobrix read for CRM lists — supersede ADR-050 D1 read half

**Status**: Accepted  
**Date**: 2026-09-02  
**Supersedes**: [ADR-050](ADR-050.md) **D1** CRM-list read model (App DB only)  
**Scope**: Matrix Sales Automation — Leads and Pipeline list/board surfaces

## Context

ADR-050 moved Leads and Pipeline lists to **App DB only** after retiring the
Qobrix service account and dropping `qobrix_opportunity_mirror`. That removed
the shared-credential leak but introduced:

- Stale list data until a full refresh walk completed
- A thin-client pagination attempt that broke the Pipeline board (`q.order is not
  a function`) and still did not match broker expectations

The **broker** leg before cutover was correct: live Qobrix under the caller's
own token, with App DB as overlay for MSA-authored state and app-only deals.
The **mirror** leg (service-harvested, admin-only) is permanently gone.

## Decision

### D1 — CRM lists read live Qobrix for all scopes

Leads and Pipeline list/board tabs call Qobrix `/opportunities` under the
**browser-held caller session** (`qFetch` via `serveQobrix`). There is no
scope branch: admins and brokers use the same live leg.

- Qobrix ACL is the row filter — MSA does **not** push down owner-id scope on
  the live fetch (`liveScope = { unrestricted: true }`).
- `trustQobrixVisibility = true` — never re-hide a row Qobrix returned using an
  MSA owner approximation.
- Restricted scopes keep `maskUnownedContactPii` as a tripwire (must stay 0 in
  normal operation).
- App DB remains the **write/copy store**: promoted rows, detail pages, contracts,
  and app-authored deals without a Qobrix id merge from `public.leads` /
  `public.opportunities` under the caller's JWT.
- **No fallback leg.** Missing or expired Qobrix session → hard fail
  (`qobrix_unavailable` / existing error panel). No silent App-DB list substitute.

### D2 — Mirror stays dropped

Do not restore `qobrix_opportunity_mirror`, service-account harvest, or
unrestricted-only mirror reads. ADR-050 D3–D6 (per-user copy refresh, admission
RPC, ownership claims) remain for warming the copy store and detail surfaces.

### D3 — Header Refresh vs admin full sync

- **Refresh** invalidates React Query (lists re-fetch live Qobrix).
- **Sync all from Qobrix** (admin) runs the chunked `qobrix-user-refresh` walk
  to warm App DB — not to populate the list.

## Consequences

- List latency follows Qobrix fan-out again (~2s p50 post campaign-cache fix).
- Sidebar badge counts that read App DB directly may disagree with live lists.
- Dual-leg merge returns for **app-authored rows only** (unavoidable while MSA
  can author deals/leads locally).
